# MateSoul 启动误入房间标定修复

最后更新：2026-10-24

## 结论

游戏存在可确认的问题：把启动时的一次空 SceneCapture 查询当成“没有房间”，
随即调用系统房间采集。原生日志没有证明用户的标定数据被删除。
已移除这一自动跳转，并在游戏内等待房间定位数据更新，提供有界等待和原地重试。

真机恢复成功尚待佩戴验证。诊断包启动后，PICO 在 Unity 业务启动前自行打开
安全边界界面，系统定位停在 `VPS_LOCALIZATION_STATE_QUERY_WAITING_6DOF_STEADY`，
头显约10秒后休眠；本次没有进入 GameBootstrap，不把安装成功计为房间加载成功。

## 原始证据

失败进程 PID32169，来自本次修复前的设备原生日志：

| 时间 | 观测 |
|---|---|
| 21:02:40.107 | SceneCapture 读取全零 mapId |
| 21:02:43.428 | SceneCapture 查询返回0锚点 |
| 21:02:43.435 | 游戏调用 StartSceneCapture，启动时间仅3.503秒 |
| 21:02:44.760 | 系统报告非零地图，距自动跳转1.325秒 |
| 随后 | RoomCapture 等待 localization init |

`StartRoomCapture` 还会清除 SDK 的内存 SceneAnchor 集合，因此不能把它当成
读取已有房间的通用恢复措施。非零地图在采集启动后出现这一事实，不单独证明
原读取流程继续等待就一定能够定位成功。

原始日志：
`/tmp/matesoul-room-relocation-20261024/before-logcat.log`，
关键行544468、546753、550130、550462。

## 实现

- `PicoSceneCaptureRoomMapProvider` 在启动 provider 前订阅
  `PXR_Manager.SceneAnchorDataUpdated`；立即查询，返回可验证的真实房间快照。
- 空查询、暂时无效的地板以及暂态 `ERROR_RUNTIME_FAILURE` 会等待更新；
  未收到事件时每2秒重新查询。调用者取消会传递；定位窗口为25秒。
- 查询期间到达的事件通过版本计数保留，避免查询结束时错过更新。
  返回、失败和取消时统一解除订阅、取消计时并停止已启动的 provider。
- 主游戏和独立导航入口均移除自动 `StartSceneCaptureAsync`；
  不写入虚构地板，不复用旧世界坐标，不重做或删除标定数据。
- `GameBootstrap.RetryLocalizationAsync` 用一个 `startupTask` 保证启动串行。
  房间未启动时重新初始化；已有 Session 时恢复原物品。
  设置→系统→重试定位可在 Session 尚未创建时使用。
