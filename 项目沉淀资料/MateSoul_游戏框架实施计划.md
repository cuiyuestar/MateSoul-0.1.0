# MateSoul 游戏框架实施计划

最后更新：2026-10-02

## 本次授权与约束

沿用 `MateSoul_Demo开发方案.md` 的 Unity/C# 技术路线与产品方向，建立可直接
演进的正式游戏内核。本次实施已获授权，无需再次进行计划审批。

用户补充：角色尺寸、移动速度、自主活动权重、阈值等可以先写死。配置、环境变量、
冗余保护本身也可能成为过度设计。使用局部代码默认值或 Inspector 字段，不建设
参数中心、配置矩阵和通用规则引擎。数据资产只承担真实内容复用。

## 运行时边界

- Core：纯 C# 动作目录、请求、生命周期、控制资源仲裁。每角色一实例，
  只有协调器驱动动作；可组合控制资源；取消与完成统一释放。
- Gameplay：纯 C# 情绪、物品实例与占用、对话编排与上下文契约、会话存档数据。
  各自状态只有一个所有者，不依赖 Unity/PICO。
- Runtime：Unity 装配、移动/动画适配、自主行为、物品与存档适配、基础 HUD。
  Unity 组件持有明确依赖，禁止全局服务定位器。
- RoomNavigation：复用已有快照和 PICO 数据源，作为引擎/设备适配层。
  旧验证场景继续用于空间回归，正式场景不挂 RoomRandomWalker。
- Editor / Tests：场景、角色 Variant、内容构建和 EditMode/PlayMode 验证。

接口只为实际边界存在。动作通过显式工厂注册，适配 IL2CPP，不使用反射扫描。
请求只给动作、目标与参数；控制资源和优先级由动作描述/可信来源确定。
UI/AI/自主行为共用目录。所有角色位移和表现通过动作持有的执行器调用。

## 实施顺序与范围

1. 工程基线：独立分支、补充 AGENTS、保留资产 GUID 和 PICO 日志线程修复。
2. 动作内核：目录、原子通道申请、抢占、取消、超时、统一释放、结构化结果。
3. 实际角色：统一移动与动画入口；接入已有房间导航；Idle/Wander、显式移动/停止。
4. 游戏基础：物品能力与占用、注册式物品动作、换装接入、情绪数值与回落、
   版本化存档、可取消对话编排、基础 HUD/字幕。
5. 扩展验证：新增动作不改协调器；第二物品实例状态独立；多个请求来源共享执行；
   情绪/服装恢复；异常/暂停/目标失效后资源释放。
6. Unity 编译、EditMode/PlayMode、Android IL2CPP 构建；可用设备上运行。
7. 更新 technical_docs / work_reports，记录实际结果和内容依赖。

框架内核与已接入能力必须可运行。牵手/坐椅、完整五面板美术、语音、长期记忆和
完整物品玩法是此框架的后续功能；不通过空动作或虚假成功假装已实现。已有生产
目录没有 SitDown/SitIdle/StandUp 动画，坐姿整链的视觉验收依赖正式动画配套。

## 状态与持久化

- 动作执行与控制权归协调器；物品可变状态和占用归物品注册表；情绪归 MoodSystem。
- 定义资产只读；定义 ID 与实例 ID 分离。
- 存档保存服装、情绪、设置、物品定义/实例/锚点相对姿态；不保存 Lease、
  Coroutine、GameObject 或 PICO handle。
- 心情沿用已确认产品规则：暂停/离线不推进时钟，等级回落不清空同类数值，
  真正退出才清空自身；不建立情绪与姿态的笛卡尔积状态机。
- 无真实模型服务配置时明确展示未连接；离线测试 Provider 只用于测试，
  不把模拟回复作为真实 AI 成功。

## 验收证据

使用 Unity Test Runner 测试资源互斥/并行、抢占、超时/取消/异常释放、目录扩展、
物品占用与移除、情绪时间规则、存档恢复、对话协议与取消。
PlayMode 运行生产角色与真实 NavMesh，检查移动、动画、暂停恢复、场景销毁和
多个来源的动作接入。构建记录报告与 SHA-256；真机 Room Capture 与完整交互
性能以实际设备测量为准，不以旧的十秒模拟器结果替代。
