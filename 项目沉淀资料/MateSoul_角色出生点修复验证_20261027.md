# 角色出生点启动失败修复验证

日期：2026-10-27  
平台：Unity 2022.3.38f1 / PICO Unity Integration SDK / Android ARM64 IL2CPP  
状态：修复、引擎回归、最终 APK 构建与头显启动验证均完成。

## 根因与证据

原运行日志中，Scene Capture 地面平均高度为 0.640m，13 个候选点全部
`noSupport=13`，`outside=0`、`overlap=0`；实时网格和环境深度已经正常启用。
捕获地面顶点高度分布为 0.42131～0.89473m，存在明显倾斜。

未修改业务逻辑的诊断包通过现有查询超时路径改用 Spatial Mesh 后，取得
实测地面平均高度 1.163313m。6 条支撑射线命中高度为 1.14003～1.17035m，
法线 Y 为 0.935～0.977，短射线正常命中；角色能够出生并达到 READY。
这证明问题是标定地面与当前实测支撑不兼容，而不是网格碰撞无法工作。
两路 SDK 数据产生偏移的内部原因尚不能确定。

## 实现

- `GameBootstrap.BuildRoomAndFindSpawnAsync` 统一构建房间、应用遮挡网格和
  搜索出生点；现有等待仍限定为 8 秒。
- 捕获房间已返回、但没有有效实测出生点时，启动入口调用现有
  `PicoSpatialMeshRoomMapProvider`，重建房间并重试一次。
  最终没有支撑仍报启动失败，取消请求继续传播。
- `RealityOcclusionMeshRenderer.ApplySnapshot` 重新入队 SDK 缓存，
  房间切换不依赖新的网格更新事件。
- 保留 0.15m 支撑高度准入、0.7 的法线 Y 阈值、角色胶囊重叠检查、
  现实碰撞与遮挡；没有固定某个绝对地面高度。
