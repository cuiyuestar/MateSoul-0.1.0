# MateSoul 现实环境光适配

> 日期：2026-10-28。范围：基础环境明暗与冷暖适配。

## 实现

- 新增 `Assets/MateSoul/Runtime/RealityAmbientLighting.cs`。房间加载、角色绑定完成后，
  `GameBootstrap` 在游戏根节点安装唯一控制器；编辑器和模拟器沿用场景照明。
- 使用当前 PICO Unity SDK 的 Light Estimation Provider。原生环境 Cubemap 固定为
  128×128，每次更新在 GPU 上均匀采样全球 64 个方向，压缩为一个 HDR 像素，
  再通过 AsyncGPUReadback 读取。采样上限为 2 次/秒，每帧只平滑更新照明参数。
- 平均亮度映射到原打光的 40%～125%，色调仅采用受限的 30% 混合。
  平滑时间常数为 1.25 秒，超过 5 秒没有有效数据时平滑恢复场景默认照明。
- 保留原主光朝向与原球谐光照的空间分布，只调整其亮度和 RGB 权重。
  冷月的脸、头发和衣服继续使用现有 Toon 材质；场景中使用同一照明的其他
  虚拟物体也会同步适配。
- 不完整、未初始化或非有限数值的 Cubemap 不进入打光。暂停时恢复默认值，
  恢复后等待新数据；禁用时立即归还照明控制权。原生贴图在 GPU 读取结束后释放。
- 原生功能启动失败时保留默认打光并输出 `MATESOUL_AMBIENT_LIGHT` 状态。

## 生产配置与 SDK 修正

`Assets/Resources/PXR_ProjectSetting.asset` 启用 `lightEstimation`，分辨率为
`PxrEnvironmentTextureResolution.Size128x128`。正常生成场景和保存场景构建入口
均保存这一配置。空间数据权限由既有房间启动流程取得，照明不另行发起权限弹窗。

验证中发现 SDK 在 Unity 脚本重载时提前读取配置：资源索引和资产导入尚未就绪，
`GetProjectConfig` 把已存在资产当成缺失，重建默认配置，连带清空 MR 和追踪开关。
仅改用 AssetDatabase 仍不足以解决导入时序，最终修正为：

1. `XR/Runtime/Scripts/PXR_ProjectSetting.cs` 在编辑器直接加载配置资产，
   Android 继续从 Resources 读取。
2. `XR/Editor/PXR_Utils.cs` 将默认宏初始化延后至 `EditorApplication.delayCall`。
3. `XR/Editor/PXR_PortalEditor.cs` 同样延后首次配置读取。

这三处属于 SDK 编辑器配置加载边界修正，不改变设备端光照算法。
