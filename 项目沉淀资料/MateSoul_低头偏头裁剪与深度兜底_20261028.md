# MateSoul 低头、偏头裁剪与深度兜底

日期：2026-10-28。平台：Unity 2022.3.38f1、URP 14、PICO Unity Integration SDK。

## 结论

已增强动态环境深度的有效性门控、滤波视野边界和近眼遮挡保护，XR 相机近裁剪面由 5cm 改为 2cm。最终 Metal GPU 与引擎专项 **48/48 通过**。

世界坐标下的实测网格、碰撞、物品和角色状态继续保留；动态深度异常时停止该层透明度合成，恢复有效数据后重新启用。缓存网格使用当前 HMD 位姿渲染，HMD 位姿继续实时更新。

## 已查明的实现路径

| 路径 | 与现象的关系 | 修正 |
|---|---|---|
| 全屏环境深度合成 | `Blend Zero SrcAlpha / ColorMask A` 会把软遮挡值乘入虚拟图像 alpha；错误的分数值能使实体半透明 | 仅使用当前成功发布的有效深度帧；不确定的均匀区域保持可见 |
| 深度相机视野边缘 | 预处理 Gather、半像素偏移与双线性滤波的采样足迹大于原半像素边界；边缘钳制会使用错误区域的数据 | 按原始深度约 3 像素扩大有效边界，并检查四个参与滤波的统计 texel |
| 深度空洞/异常值 | 0、1、NaN 等样本进入软遮挡统计可形成错误遮挡 | 任一原始邻域样本无效就标记该统计足迹未测量；插值前拒绝无效标记 |
| 隐形空间网格 | 实测网格 shader 写入深度但不写颜色，靠近或进入网格时可表现为被透明几何切除 | 距当前视点 8cm 内的网格片元不写视觉深度；物理碰撞保持原有处理 |
| XR 近裁剪 | 5cm 内的虚拟几何会被正常相机裁掉 | 主 XR 相机与构建器改为 2cm；编辑器预览相机保持其原配置 |

这些是已由本地实现和受控 GPU 输入验证的机制，不能据此认定所有现场裁剪都来自同一原因。生产角色的 SkinnedMeshRenderer 已启用离屏更新，本轮没有扩大角色 bounds 或更换角色资源。

## 数据有效性与缓存

1. `PXR_EnvironmentDepthManager` 检查原生描述获取返回值、有限位置、近单位旋转、合理 FOV 与近远平面，以及双眼纹理结构。
2. 只有深度获取与预处理成功后才发布 `LastUpdatedFrame`。`IsDepthFrameCurrent` 要求 manager 启用、深度可用且发布于当前 Unity 帧。
3. `RealityEnvironmentOcclusionFeature` 仅在上述条件成立时加入全屏环境深度合成。失败时 SDK 清空动态纹理和开关；停止更新时渲染门控拒绝旧发布帧。
4. 像素级检查再拒绝视野外、无效滤波邻域、近眼区域与没有明确前后关系的深度。有效的真实深度边缘保留软过渡。
5. 原有 `MeasuredMeshRetention` 继续保留丢失观测的实测网格，直到相同空间出现明确替换。动态深度重置不清除网格、碰撞或游戏状态。切换房间仍按原生命周期处理。

**SDK 局部补丁需在升级时保留：** 成功发布帧门控、原生 descriptor 校验、纹理尺寸变化时重建预处理目标，以及预处理无效样本标记。本地包路径是 `/Users/bytedance/MateSoul/XR`。

`LastUpdatedFrame` 表示成功获取和预处理的 Unity 帧。当前原生 descriptor 没有图像采集时间戳；若原生接口持续返回成功但内部图像已冻结，此字段不能识别传感器内容冻结。纹理 ID 会复用，不能用 ID 不变判断冻结。
