# MateSoul 眼手卡住与按钮轻触修复

日期：2026-10-24。平台：Unity 2022.3.38f1 / URP 14 / PICO Unity Integration SDK / XRI 2.5.4。

## 已完成的修改

- HUD 保留眼动瞄准、捏合后松开点击，以及食指直接点按。物品和角色维持近距离手部交互。
- 取消“手指进入整张 HUD 平面前后 5cm 就屏蔽眼手”的规则。只有食指真正接触 HUD 的可用控件才接管输入；空白区域和未接触的悬停不抢占眼手。
- 食指距控件表面 5mm 内按下，退到 15mm 外释放并允许下一次点按。缓慢或静止轻触也可响应，接触中的小幅抖动不会反复触发。
- 电视、收音机、饮水机、水壶和加热底座共 7 个按钮改为接触当帧执行。持续接触、正常松手不会二次执行；按钮原有业务准入保持生效。
- 眼手与食指指针持续注册在同一个 UI 输入模块中，通过明确的按下、释放、取消状态处理切换。失跟踪、持物或组件禁用时取消输入，恢复后要求新的捏合或退出接触区后再触碰；隐藏 HUD 也会取消眼手按下。
- 捏合进入/退出阈值为 0.75/0.55，减少必须完全张开手指才能释放的情况。握拳与抓取阈值保持原样。
- HUD 可见中心保持 45cm、视野下方 30°，操作期间冻结面板的位置和朝向。

## 确认的问题机制

旧 `HudEyeHandInteractor` 将整张 Canvas 的矩形和前后 5cm 区域作为排他区。手指停在菜单空白处也能持续关闭眼手，而用户看不到可解释的模式切换。

旧 `PicoHandPoke` 使用 `XRPokeInteractor` 的 25mm pokeDepth。XRI 的激活判定为深度比例小于 2.5%，对应约 0.625mm 前表面容差；进入条件还包含移动速度和方向检查。两种输入同时受限制时会表现为按钮没有响应。这是代码中可确认的机制，尚未用真人操作日志证明它解释了每次“卡住”。

旧实现还在物品交互管理器更新期间切换 UI 注册状态。当前手部采样、UI 和管理器的执行顺序分别为 -300、-200、-105，因此 UI 可能先处理旧状态。新实现将接触判定和状态切换都放到 UI 的本轮处理内，先处理左右食指，再处理眼手。

另外，XRI `TrackedDeviceModel.raycastPoints` 的 setter 仅按点数变化设置刷新标志。直接修改复用列表可能遗漏“眼睛静止、菜单移动”的命中变化。新实现先解绑列表再更新点位，保留原 select 状态以正确生成释放事件。
