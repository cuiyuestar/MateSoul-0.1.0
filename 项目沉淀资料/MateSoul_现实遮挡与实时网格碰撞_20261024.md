> 日期：2026-10-24

## 1. 透明遮罩的成因

代码检查确认了两个会错误裁掉虚拟内容的机制：

1. **语义包围框参与了深度渲染。** 原实现给每个房间障碍创建立方体，使用
   `ColorMask 0`、`ZWrite On` 的材料。它不显示颜色，但向深度缓冲写入整个箱体，
   所以包围框中的空隙也会遮掉后面的 UI 和物品。低头时视线穿过这些箱体，
   更容易感知到大片透明遮罩。
2. **全屏遮挡使用背景深度擦除了前景 UI。** 原环境深度合成发生在透明 UI
   绘制之后，而 UI 本身不写入 `_CameraDepthTexture`。合成使用后方地板、
   家具的深度裁剪整帧 alpha，因此可能把前方本应可见的菜单一并擦掉。

另一个已修正的边界是深度相机的视野范围：原采样没有检查每眼 UV、投影正前方和
near/far 范围。未覆盖位置的纹理采样不能代表该像素的现实深度，现已统一排除。
这属于静态确认的风险点，尚未独立完成低头触发场景的真机复现。

修复后，Scene Capture 的语义框和地板代理不产生遮挡渲染器，原碰撞箱保持。
全屏环境遮挡改为在透明物绘制前执行，HUD 背景与文字随后按各自世界位置处理
真实手部与现实物品的遮挡。Environment Depth 可用时停止粗空间网格的深度渲染，
避免两套几何叠加裁剪。

## 2. 碰撞数据的调整

| 数据 | 现在的职责 | 精度边界 |
|---|---|---|
| Scene Capture 地板、语义包围框 | 初始导航、家具语义、保守碰撞 | 箱体不代表完整现实表面 |
| 运行时 Spatial Mesh | 实测三角形、实时物理碰撞；无环境深度时作测量网格遮挡后备 | 仍受扫描覆盖和系统重建质量影响 |
| Environment Depth | 每眼视觉遮挡、真实轮廓与手部遮挡 | 视角相关深度纹理，不是 Unity 物理网格 |

原运行时 Spatial Mesh 已用于遮挡和家具识别，但未创建物理碰撞面。
现在为每个原生网格 UUID 创建静态非凸 `MeshCollider`，与渲染共享同一个 Unity Mesh。
网格更新时替换对应碰撞面，移除时释放旧碰撞和网格；Unchanged 块不重复烘焙。
同源旧测量快照的碰撞面在实时来源存在时停用，来源移除后恢复。

网格 LOD 从 **Low 提高到 High**，并在构建入口固定，避免已加载的配置实例把
磁盘修改写回 Low。最终 APK 中直接核对得到 `meshLod=2`、`spatialMesh=1`、
`environmentDepth=1`，HandsOnly 与眼动能力保留。

安全出生点检查覆盖实时碰撞面。房间导航仍保留现有地板和全部语义障碍，
没有增加每帧导航重烘焙；角色动作和物品运动继续经过原有协调器与 PhysicsBody。
