# MateSoul 直接手部交互改良

日期：2026-10-24  
平台：Unity 2022.3.38f1 / URP 14 / 本地 PICO Unity SDK 0.13.1 / XRI 2.5.4。  
范围：主 Unity 工程的输入、官方手模型、物品握取、UI 触碰、家具及保龄球放置。

## 1. 结论与原有问题

本项目适合采用“近距离手部交互”作为真机唯一默认输入。苹果等小物件要求玩家伸手接近后握住，松手释放；UI 和电器按钮由食指直接触碰。大型固定设施保留放置预览，位置跟随手掌正下方，墙面物品要求手靠近墙面。

改动前的实现与这个目标不同：

- 场景构造器生成手柄、视线和手部三类射线，物品检测距离可达 8 米。
- 手部拾取使用 pinch，自动模式可能进入 EyeHand；没有实例化官方手模型。
- `PicoHandPoke` 只接入 UI，不能单独完成物品握取。
- 家具和回收仍依赖头部视线；双拳开关菜单可能与真实握取冲突。
- SDK 的可选 pose 可能保留旧值，因此仅检查“旋转非零”不能作为有效手部姿态依据。

此次沿用项目既有的物品占用、XRI 选择、物理跟随和角色动作系统，没有修改共享 SDK、角色母版、骨骼或动画。

## 2. 行业经验如何落到本项目

| 工程原则 | 本次取舍 |
| --- | --- |
| 手部可见、近距操作、远距操作分别处理 | 官方骨骼手负责显示；掌心握取与食指触碰分开；真机关闭全部交互射线 |
| 先具备空间资格，再识别抓取意图 | 掌心距实际碰撞体表面不超过 7 cm，并要求新的张手→握紧动作 |
| 抓取后保留稳定的归属 | 每只手最多一个选中对象，XRI Single 选择及原有 ItemRegistry 继续负责竞争 |
| 跟踪不是持续可靠的输入 | 检查 SDK 返回值、isActive、关节有效/追踪标记、有限坐标和四元数；失效即释放 |
| 相机手势不要直接驱动物体 Transform | 只更新 PhysicsBody 的跟随目标，沿用碰撞约束和真实释放速度 |
| 触碰和握取需要仲裁 | 握紧或持物时关闭同手 UI 触碰；菜单双拳要求双手有效、空手、附近无候选、无放置任务 |
| 避免第一版引入复杂的手指刚体接触求解 | 使用追踪手模型和近距握取；暂不加入整手硬碰撞、手指包覆 IK 或任意物体推挤 |

7 cm、握紧 0.75 / 松开 0.35、UI poke 深度 2.5 cm 是首轮工程默认值，不是经过真机用户研究得出的最优参数。握紧/松开采用不同阈值，减少中间状态抖动。

## 3. 实现与状态归属

```text
PICO joint locations + graspValue
                 │
         PicoTrackedHand
       ┌─────────┼────────────┐
       │         │            │
 官方 PXR_Hand   掌心姿态      食指末端姿态
 骨骼与可见性    │            │
        PicoDirectHandInteractor   PicoHandPoke
                 │            │
          XRInteractionManager     既有空间 UI
                 │
       PhysicsGrabInteractable
          │                │
       ItemRegistry     PhysicsBody
       占用/释放         唯一刚体运动所有者
```

- `PicoTrackedHand`：每帧采样一次交互姿态，掌心供握取、指尖供 UI，握力供菜单和放置。显示仍由官方 `PXR_Hand` 在渲染前更新骨骼。没有有效追踪时隐藏模型并停用其骨骼更新。
- `PicoDirectHandInteractor`：无可见射线。对掌心邻域进行碰撞体查询，选最近的可选目标；检查手与目标之间的实体遮挡。查询缓冲饱和时不选择任意截断结果。
- `PhysicsGrabInteractable`：直接手握取保持物品原始相对位置与旋转，即便资产为射线模式配置了 snap，也不会瞬移到掌心。正常松开保留 PhysicsBody 的碰撞后速度；跟踪失效释放清零速度。
- `PlayerInteractionModeController`：真机固定 Gesture，禁用旧场景中的全部手柄、手部和视线射线，启动时安装双手。编辑器保留手柄模拟。已有保存场景无需重新生成。
- `VirtualItemFocusController`：真机回收目标改为手边物品；可一只手靠近、另一只手点击确认。
- `ItemPlacementPreviewController`：水平面位于实际手掌下方，垂直距离最多 2 米；墙面放置限制在手附近约 30 cm 加物品半厚度。先张手，再握紧并松开确认；中途跟踪失效或位置无效会重置确认状态。
- `BowlingGame`：球瓶/出发点采用手掌下方地面位置，确认使用新的握紧→松开。放置位置需要玩家走到对应地点；原有球道空间校验继续生效。
- UI、电器按钮和收音机旋钮继续使用现有 world-space UI：手指触碰按钮；旋钮目前仍是触碰后拖动。此次没有宣称实现了拇指/食指捏住旋钮并扭腕的专用交互。
- `HandHoldInteractable` 通过既有 `IHandHoldPoseProvider` 获得实际掌心姿态，角色行为仍提交给共享动作协调器。

抓取状态约束：

1. 进入场景、手重新出现、退出放置后，必须先张手。
2. 已经握紧再把手伸向苹果，不会拾取。
3. 靠近后新握紧，最多选中一个物品。
4. 持物后离开初始检测范围仍保持握取。
5. 松手、物品不可用、跟踪丢失或对象禁用时释放；重新追踪不能自动重抓。
6. 不可移动物品、暂停状态和 AI 占用的物品继续由原有物品准入规则拒绝。

## 4. 虚拟手的视觉边界

使用 SDK 内置 `Resources/Prefabs/HandLeft` 与 `HandRight`；只移除运行时实例上的 `RayPose`，不修改供应商资产。新增 `MateSoul/TrackedHand` URP 不透明材质，使用正常深度测试与深度写入，没有描边和永远置顶。

虚拟手不等于“删除透视画面中的真实手”。当前 PICO 透视和环境深度仍可能带来真实手边缘、模型大小偏差、相互遮挡或重影。项目现有环境遮挡在后处理后执行，会影响虚拟手；这轮没有通过关闭整场景遮挡掩盖问题。必须在真机检查，不能以桌面截图替代验收。

本轮也没有物体专用的手指包覆姿态。握苹果时模型跟随真实手关节，实际手指与虚拟苹果之间可能穿插；若验证中明显影响体验，下一步优先为常用器具制作抓握姿态和局部手指修正，再考虑软接触物理手。

## 6. 真机验收顺序

| 场景 | 预期 |
| --- | --- |
| 双手进入/退出摄像头视野，分别张合手指 | 模型实时随动；没有交互射线；失去追踪隐藏 |
| 距离苹果较远握拳 | 苹果不移动 |
| 保持握拳再伸到苹果旁 | 不自动拾取 |
| 苹果旁张手后握紧 | 只拿起最近一个苹果，没有瞬移或复制 |
| 持物移动、转腕、放到桌上、松手 | 保持相对姿态，物体碰撞桌面，松手恢复动态 |
| 持物遮住摄像头或把手移出视野 | 安全释放，手恢复时不能自动重抓 |
| 双手同时抓一个物品 | 只允许一个持有者，无争抢抖动 |
| 一手拿物、另一手点按钮 | 持物手不误点，另一手正常使用 |
| 张开食指触碰 UI、热水壶/饮水机/电视按钮 | 近距触发一次；离开后可再次触发 |
| 拖动收音机音量/调频控件 | 连续、方向正确、无跨角度突跳 |
| 空手远离物品双拳保持 0.5 秒 | 切换 HUD；拿东西时不触发 |
| 家具预览、桌面放置、墙面放置、保龄球布局 | 手掌定位、合法区域确认；丢追踪不确认、不换另一只手 |
| 固定家具、AI 正在使用的物品、暂停状态 | 不绕过现有占用与暂停规则 |
| 虚拟手在物品/UI/真实桌面前后移动 | 核对遮挡、尺寸、重影；分别记录环境深度开关状态 |

真机房间导航启动故障属于另一个正在采集证据的问题。如果尚未 `MATESOUL_READY`，不能将游戏物品未开放判断为手势拾取故障。
