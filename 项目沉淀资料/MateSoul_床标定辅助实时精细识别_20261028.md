# MateSoul：床标定辅助实时精细识别

日期：2026-10-28  
工程：`/Users/bytedance/MateSoul/MateSoul`  
平台：Unity 2022.3.38f1、URP、PICO Unity Integration SDK。

## 问题与结果

原躺床识别只提取实时空间网格中标为 Bed 的三角面，房间标定中已定位的床没有参与识别。床面分块、语义不完整、床上杂物以及不规则扫描容易造成“尚未找到足够完整的床面”。

本次复用房间标定的床身份、世界位姿和包围盒，作为实时识别不足时的局部候选依据。床面高度、范围、起伏、覆盖和障碍继续由当前实测网格确认。无实测支撑时保留“已定位床、当前床面网格不足”的提示。

## 实际识别顺序

1. 优先运行现有实时 Bed 语义识别；已成功识别的床不被标定结果覆盖，也不重复发布。
2. 仅对 `Source == "PICO Room Capture"` 的有效 Bed 标定开启辅助路径。Spatial Mesh 汇总得到的粗包围盒不作为房间标定使用。
3. 将标定床盒扩大 15cm 作为搜索容差，仅接纳完整位于该区域内的 Bed / Unknown 三角面。明确标为 Chair、Table 等其他家具的面不改语义。
4. 在距地面 35–90cm 的水平候选面中，按实测面积寻找跨度不超过 20cm 的主导高度带；不把标定盒最高点当成床面。
5. 以标定长轴指导朝向，使用实测面顶点求中心和宽长。当前宽长还须分别覆盖标定宽长的至少 65% / 70%，避免把床中间一小块扫描当作整床。
6. 复用已有面积、尺寸、覆盖与起伏检查：面积 0.8–8m²，宽 0.75–2.3m，长 1.65–2.65m，面积占外接矩形至少 45%，7×9 采样覆盖至少 55%，高度均方根误差不超过 10cm。
7. 复用枕头、结构和稳定默认头向；低矮细节保持现有 20cm 容差并参与接触高度调整。两次稳定确认并通过人体净空检查后，才发布现有 Lie capability。
8. 目标消失、床位变化或障碍出现时，沿用扫描器撤销能力和动作退出流程。原生与辅助识别切换保持原交互 ID，稳定比较继续基于几何。

## 修改文件与边界

- `Assets/MateSoul/Runtime/BedGeometry.cs`：新增接受标定列表的 Extract 重载和有效标定检查；添加 `BedTarget.CalibrationId` / `CalibrationAssisted`；辅助上床净空按局部三角面区分床框与同网格块的外部障碍。
- `Assets/MateSoul/Runtime/RealBedScanner.cs`：从当前房间快照获取已定位的床，接入辅助提取；分别显示无床候选、已定位但测量不足、稳定确认中、较高障碍和可用床。
- Editor / Development 下增加每两秒至多一次的 `MATESOUL_BED_SCAN` 本地统计：标定数、实测候选数、辅助候选数、阻挡数、可用数、三角面数。

保留当前真实网格的原语义；`RealityMeshSource` 不使用旧标定给 Unknown 全局重新贴标签。椅子识别、场景、角色、动画、碰撞所有权及动作协调器本轮未修改。

## 实际限制

- 标定盒只提供大致体积，没有专用床垫顶部高度；最终高度取实测面积主导的床面。
- 辅助路径不要求不同床面片段互相连通，但仍需要足够覆盖和实测尺寸。极少量网格、全是地面或显著超出旧标定区域的 Unknown 床面不会发布可躺目标。
- 大于现有尺寸范围的特殊床型、旋转或尺寸不可靠的标定，需要后续按真实设备样本评估。
- 没有把没有观测到更新等同于家具已经移动；网格保留机制沿用当前项目基线。
- 本轮未重新生成 APK，未安装头显；现场标定坐标精度、网格语义质量和躺床效果仍需真机验收。
